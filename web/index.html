What the analyzer sees

A Petri net lesson for developers who have not used one. Places, tokens, and a single firing — then a deadlock, a data race, and an atomicity violation, each visible on a small net.

  • place
  • transition
  • token

Plate 01

A place, a transition, one firing

A place is a circle. It stands for a condition or a resource: this thread is ready, this mutex is free, this function has ended.

A token is the dot inside a place. If the dot is there, the condition holds. These pictures use one token on each marked place.

A transition is the bar. It is an action. It may fire only when every input place holds the tokens that arc requires. Firing removes those tokens and adds tokens to the output places. The bar does not keep a token.

The net below is the shape of a mutex lock in this analyzer. TransitionType::Lock consumes one token from the mutex place (src/translate/mir_to_pn/calls.rs).

Plate 02–04

Three bugs, three readings of the net

Deadlock and data race are read off one marking. Atomicity is read off a path of firings. The pictures use the same enabling rule as the analyzer. They are teaching nets, not a dump of petrinet.dot.

Deadlock: AB-BA

Two threads, two mutexes. Thread 1 locks A, then B. Thread 2 locks B, then A. Each Lock needs a token from the thread's current place and one token from that mutex place.

DeadlockDetector walks the state graph (src/detect/deadlock.rs). A state with no outgoing edge is a deadlock when it is not a normal exit. Normal exit means a place whose name contains main_end holds a token. The entry function's end place is named {function}_end (src/translate/petri_net.rs).

If no terminal state is found, the detector also reports a stable cycle in which some lock stays disabled on every state of the cycle, and not every lock is blocked. The animation is the terminal case.

Data race: one location, two enabled accesses

DataRaceDetector looks at the outgoing edges of each state (src/detect/datarace.rs). It keeps UnsafeRead, UnsafeWrite, and each variable inside an UnsafeAccess, and groups them by location_id. Two different sites on that id are a race when at least one is a write. A read paired only with a read is not reported.

In the net below, L is that alias. It is drawn as a label, not as a place. Neither transition consumes a token from L, so both can be enabled in the same marking.

Atomicity: a remote store in the middle

AtomicityViolationDetector walks paths of the same state graph (src/detect/atomicity_violation.rs). A witness is three events on one alias. The start and the end belong to thread i. The middle event is a store from some other thread, strictly between them. AtomicLoad is a load. AtomicStore and AtomicCmpXchg are stores.

  • AV1 — load, remote store, store
  • AV2 — store, remote store, load
  • AV3 — load, remote store, load

Ordering between atomic operations is carried by ordering-segment places in the real net. The witness search itself matches kind, thread, and alias. The picture shows that order: two threads, and no mutex token between them, so the remote store can fire in the middle.

Plate 05

From MIR to a detector

pn (src/bin/pn.rs) is a rustc driver. conc_bug_detector::run starts the compiler. PTACallbacks::analyze_with_pta in src/callback.rs runs the stages below, in this order. --mode pointsto returns before the three detectors.

Plate 06

Where the code sits

Translation builds the net. The unipn crate stores the net, reduces it, and builds the state graph. Detectors only read that graph.

The README table lists src/net and src/analysis. Those directories are not in this repository. Net types, reduction, and StateGraph come from unipn.

Plate 07

What each picture is for

Deadlock

The AB-BA firing ends in a marking with no enabled transition and no token in main_end, which is the terminal state DeadlockDetector reports.

Data race

One marking enables UnsafeWrite and UnsafeRead on the same location_id, which is the conflicting pair DataRaceDetector reports.

Atomicity violation

A state-graph trace where another thread's store sits strictly between one thread's load/store events on the same alias is the AV1, AV2, or AV3 witness AtomicityViolationDetector reports.

This page does not run the analyzer. It is a lesson about the nets the analyzer builds. Crate conc_bug_detector, binaries pn and cargo pn.
